# ccaudit — Claude Code Token Usage Explorer

**Date:** 2026-03-21
**Status:** Approved

---

## Overview

`ccaudit` is an interactive terminal UI tool for exploring Claude Code token usage by analysing local conversation logs at `~/.claude/projects/`. It lets you drill down from a global view all the way to individual context categories within a single conversation turn.

---

## Goals

- Visualise token usage across all Claude Code projects and sessions
- Drill down from global → project → session → turn → category → items
- Identify which categories (skills, memory, system prompt, tools, messages, agents) consume the most tokens
- Use actual API-recorded token counts (not estimates) as the source of truth

---

## Non-Goals

- Real-time monitoring (single load at startup, lazy per-project)
- Billing calculations or cost reporting (token counts only)
- Writing or modifying conversation logs

---

## Data Source

Files: `~/.claude/projects/<project-slug>/*.jsonl`

Each line is a JSON object. Relevant message types:

| Type | Used for |
|---|---|
| `assistant` | `message.usage` — `input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens` |
| `user` | `message.content` — full context text for category scanning |
| `system/compact_boundary` | `compactMetadata.preTokens` — marks context resets |

### Token Types

| Field | Meaning |
|---|---|
| `input_tokens` | Fresh tokens not served from cache (tiny per turn — typically the new user message) |
| `cache_read_input_tokens` | Tokens read from prior cache (accumulated: system prompt + previously cached skills/history) |
| `cache_creation_input_tokens` | New tokens being cached this turn (new skills loaded, memory files, conversation crossing a cache breakpoint) |
| `output_tokens` | Tokens generated by the assistant |

**Note:** `cache_read` grows cumulatively across a session — it represents the entire prior context window. It cannot be cleanly split by category per-turn. Per-session totals are more meaningful than per-turn cache attribution.

## Hierarchy

```
[ALL PROJECTS]           ← global aggregate
  └── <project>          ← per project (one dir in ~/.claude/projects/)
        └── <session>    ← per .jsonl file
              └── turn N ← per assistant message
                    └── <category>   ← Skills / Memory / System Prompt / Tools / Agents / Messages
                          └── <item> ← individual named item within category
```

---

## Category Detection Heuristics

The preceding `user` message content block(s) for each turn are scanned top-to-bottom and split into character buckets per category. Token counts are then attributed **proportionally**:

```
category_tokens = (category_char_count / total_char_count) × actual_input_tokens
```

This ensures all categories sum exactly to the recorded `input_tokens` for the turn.

| Category | Detection marker |
|---|---|
| **Skills** | Block starting with `Base directory: /...skills/...` followed by markdown `# Heading` |
| **Memory** | Block matching `---\nname: ...\ntype: ...\n---` YAML frontmatter |
| **System/Tools** | `<system-reminder>` tags and tool result blocks |
| **Agents** | Tool use blocks where tool name is `Agent` or contains subagent output |
| **System Prompt** | Estimated from first turn's `cache_read_input_tokens` baseline (~9,550 tokens consistently) |
| **Messages** | Everything else — prior conversation history |

Items within each category extract their name from the marker (e.g., skill title from the `# Heading`, memory name from the `name:` field).

## TUI Layout

Built with [Textual](https://github.com/Textualize/textual). Split-pane layout:

```
┌─────────────────────────┬──────────────────────────────────────┐
│  TREE                   │  DETAIL                              │
│                         │                                      │
│  ▼ [ALL PROJECTS]       │  Category          Tokens    %       │
│    ▼ feedr              │  ─────────────────────────────────   │
│      ▼ session abc123   │  Messages          45,230   54%      │
│        ▼ turn 14        │  System Prompt      9,550   11%      │
│          > Skills       │  Skills             8,416   10%      │
│          > Messages     │  Tools              6,200    7%      │
│        turn 13          │  Memory             4,100    5%      │
│      session def456     │  Agents             1,200    1%      │
│    ccaudit              │                                      │
│    habsburg             │  ── Token Totals ──                  │
│                         │  Input (fresh)      3,420            │
│                         │  Cache read        74,696            │
│                         │  Cache write        8,416            │
│                         │  Output             1,832            │
└─────────────────────────┴──────────────────────────────────────┘
 [q] quit  [↑↓] navigate  [enter/space] expand  [/] filter
```

- **Left pane**: collapsible tree. Selecting any node updates the right pane.
- **Right pane**: aggregated category breakdown table + token totals for the selected node.
- **`/` filter**: fuzzy-filter tree nodes by name.
- **Mouse support**: click to select and expand nodes.

## Module Structure

```
ccaudit/
├── ccaudit.py              # entry point
├── parser/
│   ├── __init__.py
│   ├── loader.py           # scans ~/.claude/projects/, loads .jsonl files
│   ├── models.py           # dataclasses: GlobalStats, ProjectStats, SessionStats, TurnStats, CategoryBreakdown
│   └── categorizer.py      # heuristic text scanning → proportional token attribution
├── tui/
│   ├── __init__.py
│   ├── app.py              # Textual App, layout
│   ├── tree.py             # left pane tree widget
│   └── detail.py           # right pane DataTable
└── requirements.txt        # textual
```

**Data flow:**

```
loader.py → raw JSONL dicts
  → models.py → typed stats tree
  → categorizer.py → CategoryBreakdown per turn
  → tui/tree.py → tree nodes bound to stats objects
  → tui/detail.py → renders selected node's breakdown
```

Parsing is lazy: project data is loaded on first expand in the tree.

---

## Key Decisions

- **Python + Textual**: rich TUI primitives (Tree, DataTable), keyboard + mouse, minimal dependencies.
- **Proportional attribution**: category tokens always sum to actual `input_tokens` — no estimation drift.
- **Lazy loading**: startup is instant; heavy JSONL parsing only happens when a project is expanded.
- **Read-only**: never writes to `~/.claude/projects/`.
